# Звіт про редизайн — Bless Cuts

## Що було

Живий one-page сайт реального барбершопу (Львів), HTML/CSS/JS без залежностей, на GitHub Pages. Сильна візуальна мова ("Liquid Glass") і реальний, живий контент (8 майстрів, повний прайс, реальні фото) — але без базового SEO, з кількома пропущеними станами доступності і неоптимізованими зображеннями.

## Що знайдено (`02-audit.md`, топ-10)

1. 0 із 4 базових SEO-елементів (meta description, OG, schema.org, sitemap/robots).
2. Відсутні `:focus-visible` стилі — критично для клавіатурної навігації.
3. axe-core: 1 реальний contrast violation (`.foot-bottom`) + 1 incomplete (nav над фото).
4. FAQ відсутній — реальні заперечення клієнтів не закриті текстом.
5. Немає sticky CTA запису на мобільному під час глибокого скролу.
6. 4.1 MB зображень без WebP/AVIF.
7–10. Дрібніші: heading-хаєрархія (h4 без h3), Esc/focus-return у мобільному меню, мертві CSS-токени, один неточний пункт аудиту (дитяча стрижка — виправлено на "вже ОК" після перевірки коду).

## Що зроблено

| Категорія | Дія | Результат |
|---|---|---|
| SEO | meta description, Open Graph, Twitter Card, `schema.org/HairSalon` + `FAQPage` JSON-LD, `sitemap.xml`, `robots.txt`, `<link rel="canonical">` | з 0 до повного базового набору |
| Доступність | `:focus-visible` на всіх посиланнях/кнопках (контекстний колір — білий на темних секціях, чорний на світлих); контраст `.foot-bottom` і `.nav-links` піднято; footer `<h4>`→`<h3>` (без розриву ієрархії); Esc закриває мобільне меню й повертає фокус на бургер | axe-core: **1 violation → 0**, 15 passes → 16 |
| Контент | Додано секцію FAQ (6 реальних питань/відповідей), пункт меню "Питання" | Закриває евристику Нільсена №10 |
| Мобільний UX | Sticky-бар "Записатися онлайн" внизу екрана під час скролу | Прямий доступ до головної конверсійної дії з будь-якої точки сторінки |
| Продуктивність | Усі 17 фото сконвертовано в WebP (`<picture>`+fallback JPG), підключено і в статичній розмітці, і в JS-шаблоні карток майстрів | **3.9 MB → 1.06 MB зображень (-73%)** |
| Дизайн-система | Мертві CSS-токени (`--glass-light-*`, невикористаний `--radius-sm`) прибрано; робочі значення скла зведено в `--glass-fill`/`--glass-border`/`--glass-blur` — одна точка правки замість пошуку по файлу | Технічний борг закрито, задокументовано в `04-design-system.md` |

## Що свідомо НЕ зроблено (і чому)

- **Не вигадано фіктивний бізнес** — сайт лишився сайтом реального Bless Cuts (`DECISIONS.md` #1).
- **Не замінено Liquid Glass на нову концепцію** — вона вже затверджена власником через десятки ітерацій цього ж проєкту (#2).
- **Не додано мок-форму запису** — реальний Altegio-флоу вже працює, фейковий степер був би регресом (#3, #7).
- **Не роздроблено на багатосторінковість** — контенту достатньо для one-pager, дроблення зламало б зовнішні посилання (#4).
- **Не запущено живий Lighthouse** — середовище без мережевого доступу до Chrome DevTools Protocol для аудиту через CLI; замість вигаданих цифр використано прямий статичний аналіз ваги ресурсів (чесно позначено в `02-audit.md`, розділ "Продуктивність").
- **Не додано `ratingCount` у schema.org** — точна кількість Google-відгуків невідома; вигадування цифри для розмітки було б саме тим фейковим соціальним доказом, якого проєкт свідомо уникає.
